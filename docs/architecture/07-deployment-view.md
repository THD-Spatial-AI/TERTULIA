# Deployment View

The whole platform is **self-hosted via Docker Compose** — one stack, one network,
no managed cloud. The root `docker-compose.yml` runs the workshop app, its database
and auth, and the feedback pipeline together.

## Production / single-host Deployment

```
Docker host (tertulia network)
    │
    ├── frontend            :8080 → :80    React 19 SPA (nginx-served static build)
    │
    ├── backend             :8010 → :8001  FastAPI (Uvicorn)
    │       ├── asyncpg   ──► postgres
    │       ├── auth      ──► auth-service (validates facilitator session)
    │       ├── WebSocket ──► in-process hub (session:{slug}:control / :presence / :reactions)
    │       └── httpx     ──► feedback-pipeline  /api/v1/persona/pre-register
    │
    ├── auth-service        :8002 → :8001  Go auth-service (OIDC broker)
    │       ├── keycloak  ──► Keycloak
    │       └── redis     ──► session store
    │
    ├── keycloak            :8185 → :8080  Keycloak (OpenID Connect IdP)
    ├── postgres            :5435 → :5432  PostgreSQL 16 (schema: backend/db/schema.sql)
    ├── redis                              auth-service session store
    │
    ├── feedback-pipeline   :9000 → :8000  FastAPI (issue generation + reports)
    │       └── n8n webhooks ──► ollama
    ├── n8n                 :5678          workflow orchestration (vision + process)
    └── ollama              :11434         local LLM inference (GPU, or CPU override)

External: https://wildfire.thd-spatial-ai.de  (separate project, Storcito-Wildfire)
```

## Local Development

```
Developer Machine
    │
    ├── docker compose up -d            full self-hosted stack (above)
    │       or  make up-cpu             same, without an NVIDIA GPU
    │
    └── native (no Docker):
        ├── http://localhost:5173       Vite dev server (React SPA, HMR)
        └── http://localhost:8001       Uvicorn FastAPI backend (--reload)
            (still needs postgres + keycloak + auth-service running via compose)
```

`docker compose -f docker-compose.yml -f docker-compose.dev.yml up backend frontend-dev`
runs the backend with hot-reload and a Vite dev container (`make dev-docker`).

## Environment Configuration

All configuration lives in a single root `.env` (see `.env.example`; `make env`
creates it and generates `N8N_ENCRYPTION_KEY`). Key variables:

```
# Database
POSTGRES_USER / POSTGRES_PASSWORD / POSTGRES_DB / POSTGRES_PORT

# Auth (Keycloak + Go auth-service)
KEYCLOAK_CLIENT_ID / KEYCLOAK_CLIENT_SECRET / AUTH_REALM
AUTH_INTERNAL_SECRET            # openssl rand -base64 48
STORCITO_REPO_PATH              # path to the storcito monorepo (builds auth-service)

# Feedback pipeline handoff
PIPELINE_TOKEN                  # == pipeline WORKSHOP_TOKEN == overlay workshopToken
WILDFIRE_BASE_URL
GITHUB_TOKEN / GITHUB_REPO      # where feedback issues are filed
N8N_ENCRYPTION_KEY              # per-machine, generated by `make env`
GROQ_API_KEY                    # OPTIONAL cloud accelerator; empty = local Ollama
```

The backend also reads `backend/.env` (`DATABASE_URL`, `AUTH_SERVICE_URL`, etc.);
in the unified compose the pipeline-facing values are injected from the root `.env`.

## Deployment Steps

1. `make env` — create `.env` files and generate the n8n encryption key.
2. Fill in `.env`: `PIPELINE_TOKEN`, `KEYCLOAK_CLIENT_SECRET`, `AUTH_INTERNAL_SECRET`,
   `GITHUB_TOKEN`, `GITHUB_REPO`.
3. `make up` (GPU) or `make up-cpu` (no GPU) — build and start the whole stack.
4. `make models` — pull the two Ollama models (`qwen2.5:14b`, `qwen2.5vl:7b`).
5. Import + activate the two n8n workflows (`pipeline/n8n-workflows/`) at `http://localhost:5678`.
6. In Keycloak (`http://localhost:8185`), create the `tertulia` realm client and paste
   its secret into `KEYCLOAK_CLIENT_SECRET`.
7. Apply the DB schema — mounted automatically from `backend/db/schema.sql` on first
   `postgres` start.
