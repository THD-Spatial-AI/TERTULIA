# Glossary

## Domain Terms

**Workshop Session**
A bounded facilitated event where a group of stakeholders (participants) collaborate on structured templates under the guidance of a facilitator. Corresponds to one record in the `sessions` table.

**Facilitator**
The THD Spatial AI team member who creates and controls a workshop session. Has an authenticated account (Supabase magic link). Controls phase transitions, template unlocking, and the Wildfire launch.

**Participant**
A domain expert (firefighter, mayor, scientist, academic) who joins a workshop session anonymously (name + role + org only). Fills in collaborative templates.

**workshop_tag**
A string identifier shared across the workshop session, feeedback_pipeline, and Wildfire URL params. Used to group all feedback from a specific event (e.g., `workshop-2026-munich`). Acts as the foreign key between the three systems.

**session_token**
A UUID v4 generated by the backend on participant join. Stored in the participant's browser `localStorage`. Used to authenticate template writes and to pre-register personas with feeedback_pipeline. Never shared with other participants.

**Phase**
The current state of a workshop session. Values: `lobby → slides → template_1 → template_2 → template_3 → template_4 → launched`. Controlled by the facilitator.

**Persona Card**
Template 1. A structured form where a participant captures who they are in the context of the workshop: role, goals, pain points, tech comfort level.

**User Flow**
Template 2. A linear step editor where a participant maps their intended journey through the Wildfire application.

**Problem / Opportunity Board**
Template 3. A sticky-note grid where a participant captures the real-world problems they face and opportunities the platform could address. Notes are typed as `problem` (red) or `opportunity` (green).

**Stakeholder Map**
Template 4. A freeform node-edge graph where a participant maps the people and organizations they coordinate with during a wildfire event.

**Push Redirect**
The mechanism by which the facilitator simultaneously navigates all connected participants to the Wildfire application URL. Implemented via Supabase Realtime broadcast on `session:{id}:control`.

**Pre-registration**
The act of sending a participant's persona data to feeedback_pipeline before the Wildfire redirect, so the `PersonaForm` in Wildfire's `FeedbackOverlay` is skipped.

## Technical Terms

**Supabase Realtime**
Supabase's WebSocket-based broadcast system. Used for syncing phase changes, slide index, participant presence, and reactions across all connected browsers.

**feeedback_pipeline**
The companion project at `C:\Users\user\Desktop\STORCITO\feeedback_pipeline`. Captures in-app feedback from Wildfire, processes it with local AI (Ollama), and creates GitHub issues. Receives pre-registered personas from the workshop platform.

**FeedbackOverlay**
The React component from feeedback_pipeline (`frontend_overlay/src/FeedbackOverlay.tsx`) that wraps the Wildfire app root and provides the floating action button for in-app feedback.

**session_token (pipeline)**
Same concept as `session_token` in the workshop platform. When passed to Wildfire as a URL query param (`?session_token=...`), the FeedbackOverlay uses it to look up the pre-registered persona and skip the PersonaForm.

**Magic Link**
Supabase Auth's passwordless email authentication. Facilitator enters email → receives a one-click login link → authenticated session established.

**RLS (Row Level Security)**
Supabase's PostgreSQL-level access control. Ensures participants can only read/write their own template rows, and facilitators can only control their own sessions.

**Arc42**
The software architecture documentation template used by THD Spatial AI projects. This documentation follows the standard 12-section Arc42 structure.
